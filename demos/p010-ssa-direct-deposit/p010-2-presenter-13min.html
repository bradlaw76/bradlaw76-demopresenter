    Use real screens where accepted; label prepared or preview screens. Don't wait on an unready chat widget or execute a banking write for this rehearsal.

    Presenter-safe route

    Three presentation risks to manage

    • Two different people. Sofía asks for a benefit letter by voice; Elena separately asks about a direct-deposit alert through the portal. There is no voice-to-chat transfer.
    • Chat is conditional. The portal page exists, but the live chat widget / human escalation needs runtime acceptance. Pivot to a labeled prepared representative screen when required.
    • Banking is protected. The Dataverse verification flag and editable form have persistence evidence, but trusted update → clear same-row flag → portal refresh is not an accepted end-to-end flow. Leave the Case pending today.

    Ask the team at the end

    1. Did the change from Sofía's voice call to Elena's digital case make sense?
    2. Which screen changes seemed unnecessary or confusing?
    3. Was it clear what is available today versus still being implemented?
